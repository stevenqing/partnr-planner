# VIKI-L2 结果（论文用）

整理 2026-09-02。所有数字由 `scripts/viki_report_matrix.py` 从已归档的**原始模型响应**统一重算
（seed 20260829），不继承任何旧 summary。该脚本独立复算出 G-Memory 471/924 = 50.97%、与归档一致。

---

## 1. 实验设置

**三个 split**

| split | 规模 | 构造 |
|---|---|---|
| ID | 924 行 | 官方评测 manifest |
| 留出族 OOD | 924 行 × 8 折 | 每折把该族全部训练 episode 移除后再评测该族，记忆按"该族从未存在"重建 |
| 组合泛化 | 297 行 × 带图/纯文本 | 每行同时要求切割（双机器人）与搬运（单机器人），两种模式从未在同一条训练轨迹里共现 |

组合泛化 split 跑分前已冻结（`freeze.json` 含数据集/生成器/runner/格式工具的 sha256）。

**打分口径。** 官方 `format_reward` / `acc_reward` 用 `ast.literal_eval` 解析 `<answer>`；
Python 字面量没有 `null`，模型按 JSON 习惯给空闲机器人写 `"R1": null` 就整行判 0，与规划正确与否无关
（G-Memory 有 735/924 = 79.5% 的行因此判 0）。**全文统一使用 JSON-tolerant 口径**：
改用 `json.loads` 并丢弃 null action，其余判据（模拟器执行 + `len(gt)/len(pred) >= 0.99` 长度上限）
与官方完全一致。同一批响应上 G-Memory 官方 9.85% → tolerant 50.97%。

**prompt 条件。** 归档各基线臂拥有 partner prefix（含参考计划第 1 步的伙伴动作），
**本方法没有**——因此本文的比较对我们偏保守。

**ID 的读法。** 924 行测试指令有 855 行（92.5%）逐字出现在训练池，top-5 照抄天花板 78.9%。
ID 分数因此同时衡量检索召回率；方法层结论以留出族 OOD 与组合泛化两个 split 为准。

## 4. 本方法的消融

### 4.1 委派曲线：LLM 该在哪一层

同一份记忆、同一个模型、同一批 924 行、同一套口径，**只改变"问模型什么"**：

| LLM 被要求做的事 | ID |
|---|---|
| 整个动作序列（记忆渲染成散文） | 8.66% |
| 整个动作序列（记忆是 v1 技能文本） | 16.77% |
| 整个动作序列（记忆是轨迹 = G-Memory） | 50.97% |
| 变体 + 绑定 + 派工（**体**菜单） | 38.74% |
| 做什么 + 用什么 + 谁来做（**意图**菜单） | 67.42% |
| 做什么 + 用什么（**记忆派工** = 本方法） | **91.56%** |
| 只说"什么必须成真" | 98.16% |
| oracle 目标谓词（天花板） | 100.00% |

**在 ID 上单调：每多委派一分组合工作就掉一截。**

**这条单调性只在训练分布内成立。** 曲线倒数第二、第三档（记忆派工 91.56% 与
LLM 派工 67.42%）在组合泛化 split 上顺序**反转**——65.99% 对 79.80%，零反例。
见 §4.4。所以这张表要写成"ID 上的委派曲线"，不能写成方法的普遍性质。

两点读法：

- **同一份记忆内容，散文 8.66% vs 可执行算子 91.56%。** 这直接检验了"技能可以只是自然语言"
  这一假设——差 83 点。
- **体菜单 38.74% 低于意图菜单 67.42%，是接口设计的结果。** 算子体的适用条件是隐藏世界状态
  （柜子是否关着、东西是否在容器里），把前置条件当选择依据暴露给模型是要求它推断图中不可见的量；
  改成按**意图**暴露（put / use / open）后，同一批 120 行样本 32.5% → 96.7%。

### 4.2 三层结构消融（三个模型，同一批答案离线重打分，零新增 token）

记忆派工：

| 模型 | 完整 | −Layer 2（顺序） | −Layer 3（接地） | 两者都去 |
|---|---|---|---|---|
| 72B | 91.56% | 72.29% | 43.18% | 43.18% |
| 30B | 79.00% | 63.10% | 52.49% | 50.76% |
| 7B | 21.75% | 14.07% | 12.12% | 11.15% |

LLM 派工（分子/924：623/445/281/281、471/337/304/291、148/61/71/58）：

| 模型 | 完整 | −Layer 2（顺序） | −Layer 3（接地） | 两者都去 |
|---|---|---|---|---|
| 72B | 67.42% | 48.16% | 30.41% | 30.41% |
| 30B | 50.97% | 36.47% | 32.90% | 31.49% |

**两层在三个模型、两条派工臂上都有实质贡献**，不是 72B 特有，也不是某一条派工臂特有。

### 4.3 顺序由谁提供

| 顺序来源 | ID |
|---|---|
| 记忆挖出的排序规则 | **98.16%** |
| 模型自己给顺序 | 77.38% |

记忆挖出的规则只有 3 条，全部 precision 1.0、训练集 recall 1.0、假顺序 0：

| 规则 | 支持 | 出现族 |
|---|---|---|
| A(放置) → B(激活)，当 B 的算子体去了 A 放置的地点 | 630/630 | cut_fruit, cut_two_fruits |
| A(放置) → B(激活)，当 A 的目标就是 B 本身且 B 体访问它 | 441/441 | toast_bread, wash_fruit |
| A(放置) → B(放置)，当 A 的主体是 B 的目标 | 206/206 | set_plate |

第一条最能说明问题：切水果那对谓词**结构上毫无关联**（水果@砧板 vs 刀被激活），
只有借 Layer 1 的算子体"用刀时会去砧板"才能发现。**Layer 2 依赖 Layer 1，这是三层耦合处。**

### 4.4 派工由谁决定：**方向随 split 反转**

两条臂共用同一份记忆、逐字节相同的 prompt（意图菜单是一个固定常量，其中包含
`robots` 字段），差别只在消费端是否采纳模型给出的机器人指派。因此这一格可以在归档响应上
离线重打分，零 token。自检：LLM 派工那批响应在记忆派工下重打分得 846/924 = 91.56%，
与记忆派工自己那批**完全一致**，所以两条臂之间的差不含任何重采样方差。

| split | 记忆派工 | LLM 派工 | 配对（LLM 胜/负） | p |
|---|---|---|---|---|
| ID (924) | **846 = 91.56%** | 623 = 67.42% | **0 / 223** | 1.5e-67 |
| 留出族 OOD (924) | **829 = 89.72%** | 606 = 65.58% | — | — |
| 组合泛化·带图 (297) | 196 = 65.99% | **237 = 79.80%** | **41 / 0** | 9.1e-13 |
| 组合泛化·纯文本 (297) | 194 = 65.32% | **259 = 87.21%** | **65 / 0** | 5.4e-20 |
| 组合泛化·带图 30B | 174 = 58.59% | **196 = 65.99%** | 26 / 4 | 5.9e-05 |
| 组合泛化·纯文本 30B | 181 = 60.94% | **218 = 73.40%** | 42 / 5 | 2.5e-08 |

**两个方向都是零反例**：训练分布内 223 行记忆派工赢、模型一行没赢；组合泛化上 65 行模型派工赢、
记忆一行没赢。

**机制在计划长度里，不在目标理解里**：

| 臂 / split | 计划长度 | 参考 | 在预算内 | 模型指派不可行而回退 |
|---|---|---|---|---|
| 记忆 / ID | 6.61 | 6.90 | **895/895 = 100%** | — |
| LLM / ID | 7.23 | 6.90 | 672/895 = **75.1%** | 29/924 = 3.1% |
| 记忆 / 组合泛化带图 | 7.29 | 11.22 | 260/297 = 87.5% | — |
| LLM / 组合泛化带图 | 7.87 | 11.22 | **297/297 = 100%** | 0 |
| 记忆 / 组合泛化文本 | 7.78 | 11.22 | 253/297 = 85.2% | — |
| LLM / 组合泛化文本 | 8.28 | 11.22 | **297/297 = 100%** | 0 |

ID 上模型的指派把 24.1% 的行撑爆 `len(gt)/len(pred) >= 0.99`；组合泛化上反过来，
记忆的代价搜索有 8–15% 的行超预算、模型的指派一行都没有。

**解释**：ID 有 92.5% 逐字泄漏（§1），记忆的代价搜索在训练分布内接近最优，模型的指派只是噪声。
组合泛化的每一行同时要求切割（双机器人）与搬运（单机器人），而这两种模式**从未在同一条训练轨迹里
共现**——记忆里没有"哪个机器人干哪一半"的先例可依，模型有。
**派工不是一个可以一次性定死的接口选择，它取决于记忆是否见过这种组合。**

### 4.5 留出族 8 折：算子是否真的跨族迁移

每折把两层记忆都按"该族从未存在"重建——算子从其余族重新归纳、排序规则重新挖掘、
词表重新收集。模型的答案从归档运行里回放，所以**整折实验零 token，也不可能因为重新采样而移动**。
逐折数字由 `viki_eval_v2_intent_folds.py --responses <tag> --crew <arm>` 实测；
该脚本在全量记忆上复现出归档的 846/924 与 623/924，这是它可信的自检。

| 族（行数） | 记忆派工 fold | 记忆派工 full | LLM 派工 fold | LLM 派工 full |
|---|---|---|---|---|
| clear_table (220) | 220/220 | 220/220 | 105/220 | 105/220 |
| cut_fruit (189) | 178/189 | 178/189 | 178/189 | 178/189 |
| cut_two_fruits (108) | 82/108 | 82/108 | 82/108 | 82/108 |
| **dog_push (46)** | **0/46** | 17/46 | **0/46** | 17/46 |
| ensure_all_fruits (82) | 70/82 | 70/82 | 70/82 | 70/82 |
| parallel_human (86) | 86/86 | 86/86 | 86/86 | 86/86 |
| set_plate (85) | 85/85 | 85/85 | 85/85 | 85/85 |
| toast_bread (108) | 108/108 | 108/108 | **0/108** | **0/108** |
| **合计** | **829/924 = 89.72%** | 846/924 = 91.56% | **606/924 = 65.58%** | 623/924 = 67.42% |

**两条臂的折次代价都是 1.84 点，而且都完全来自 dog_push 一族**——其余七折的 fold 与 full
**逐行相同**，留出整个任务族不花任何代价。

**为什么 dog_push 恢复不了**：统计 14 个训练族的动作原语，`Push` **只出现在这一个族**。
留出该族等于把这个原语整个从数据里抽走，任何归纳都恢复不了。这是 benchmark 的覆盖性质，
不是方法的缺陷。注意它在**全量**记忆下也只有 17/46 = 37.0%，所以这一族的困难不止于折次。

**toast_bread 是两条臂唯一分歧的族**：记忆派工 108/108，LLM 派工 0/108，与折次无关。
该族要求两个机器人的时序配合，正是 §4.4 量到的模型最弱的那个子决定。

### 4.6 组合器的上下界

以下各行属于**组合器路线**（目标谓词直接输入，机器人由组合器自身搜索分配），
早于意图接口，**与派工来源无关**——这条线上模型从不指派机器人，所以没有 LLM 派工的对应值。

| | ID (924) |
|---|---|
| 组合器 + oracle 目标谓词 | **100.00%** |
| 组合器 + 零样本目标解析（不使用记忆） | 94.70% |
| 只用 7 个通用宏（去掉推箱接力） | 95.02% |
| 对"哪些目标已满足"完全无知（`--blind-state`） | 100.00% |
| 目标谓词换成别行的（控制，`--shuffle-goals`） | 2.49% |

同一条线上的留出族对照（**同样属于组合器路线，不是意图臂**）：

| | 924 行 |
|---|---|
| 留出族记忆 | 867/924 = 93.8% |
| 全量记忆 | 913/924 = 98.8% |
| 手写宏（读完全部 8 个族之后写的作弊上界） | 913/924 = 98.8% |
| 留出族算子 + 全量词表 | 867/924 = 93.8%（损失全在算子，不在词表） |

八折里七折与全量记忆、手写宏三者逐行相同。**这四行不能与 §4.5 混用**：
它们的输入是目标谓词，§4.5 的输入是模型写的意图。

计划长度均值 6.67 vs 参考 6.91，**100% 在预算内**；参考计划本身 40/40 被接受；format 100%。
调度器用官方 `Checker` / `SimEnv` **本体**逐步推进，不重写世界模型，
所以"规划器与 judge 不一致"这类偏差结构上不存在。
**等待行为是涌现的**——机器人面对未开的柜子即不可行、原地重试，代码中没有任何关于等待的规则。

### 4.7 图像的净贡献

组合泛化 split 的带图 / 纯文本两版是同一批行的配对设计：

| 方法 | 带图 | 纯文本 | 配对 |
|---|---|---|---|
| skill memory v2，**记忆派工** | 65.99% | 65.32% | 持平 |
| skill memory v2，**LLM 派工** | 79.80% | **87.21%** | **文本胜 28/6，p=0.0002** |
| G-Memory | 4.7% | 3.4% | n.s. |
| 其余基线 | — | — | 全部 n.s.（p=0.48–1.0） |

**"图像净贡献为零"这条结论是派工臂相关的，措辞必须收紧。** 在记忆派工与全部基线上，
带图与纯文本配对无差异；但在 LLM 派工上，**给图反而掉 7.4 点且显著**——模型要指派机器人时，
图像是干扰而非信息。可写的稳妥版本是：**没有任何一条臂从图像获得收益**，
其中一条还因此受损。

一处值得写的细节：G-Memory 的**切割子目标**带图 46.5% → 纯文本 17.8%，
本方法在同一子目标上几乎不变（9.1% / 10.1%）。图像对它的子目标推理有实质帮助，
但没有传导到最终分——因为最终分卡在步数预算上（见 §4.9）。
所以"图像净贡献为零"是**最终分层面**的结论,不是"图像对任何中间量都无用"。

### 4.8 记忆产物本身

| | v1 | v2 |
|---|---|---|
| 单元 | 轨迹派生的文本 demo | 带类型的算子（effect / body / 前置 / 能力 / 代价） |
| 索引 | 指令 embedding | effect + 世界事实 |
| 返回 | prompt 文本 | 可执行算子 |
| 规模 | 411 individual + 412 coop | **19 个算子**（10 achievement / 1 repair / 8 coordination） |
| 验证 | 无 | 建后自检：**120/120** held-out 训练轨迹被官方 judge 判对 |

**跨族证据**：最高支持度的算子是 cost-5 的 deliver，**support 2500，从 8 个不同族归纳出来**。
这是留出一个族几乎不花钱（−1.9 点，§4.5）的直接原因。

**归纳机制的自检**：3356 条训练参考计划回放**全部可行、无一留下未满足谓词**。

**归纳出的算子比手写的更好**，三个具体例子：

- `?x @ ?y` cost 7 **when target_sealed**，body 内联 `[Reach ?y][Open ?y]`——
  开柜是送货途中的插入而非独立一趟，所以 clear_table 能压进 7 步；手写版把开柜拆成独立链，
  需要额外搜索才凑出同样长度。
- 同效果另有 cost 5 **when target_sealed** 的变体，runner 是 `fetch`（单手，抱着东西开不了柜）
  ——**库自己学到了分工**。
- `?x activated` cost 6 = `[Move ?x][Reach ?x][Grasp ?x][Move ?z1][Reach ?z1][Interact ?x]`：
  切水果要**把刀带到砧板**。手写的 activate 只有 `[Move][Interact]`。

**协作算子的判据是可执行的**：`run_alone()`——单机器人段单独回放能否达成该谓词；
不能就把窗口内所有机器人的段一起归纳成带角色变量与跨角色先后计数的算子。
角色变量在**调度时**绑定（哪个机器人担任哪个角色由分配搜索决定）。

### 4.9 失败模式的分解（两个 split 的瓶颈不同）

| split | 主要失败模式 | 证据 |
|---|---|---|
| 留出族 OOD | 目标未达成 | 86.9% 的失败是 goal not reached |
| 组合泛化 | **计划效率** | G-Memory 有 **21.2% 的行两个目标都达成**（切割 46.5%、搬运 24.2%），最终只得 4.7%——差的 16.5 点全部输在 `len(gt)/len(pred) >= 0.99` 的步数上限 |

**这解释了为什么"记忆提供更多内容"在组合泛化上无效，而"记忆约束步数预算"有效**：
本方法的组合器计划长度均值 6.61 vs 参考 6.90、100% 在预算内（§4.4），
是它在这个 split 上从 4.7% 跳到 65.99% 的直接原因。

本方法自己的失败分解（72B，逐行实测）：

| 臂 / split | SOLVED | OVER_BUDGET | GOAL_UNMET | 其他 |
|---|---|---|---|---|
| 记忆派工 / ID | 91.56% | ~0% | — | — |
| LLM 派工 / ID | 67.42% | **24.10%** | 5.30% | 3.2%（无算子/无排程） |
| LLM 派工 / OOD fold | 65.58% | **24.10%** | 5.30% | 5.0% UNSUPPORTED |
| LLM 派工 / 组合泛化带图 | 79.80% | **0%** | 20.20% | 0 |
| LLM 派工 / 组合泛化纯文本 | 87.21% | **0%** | 12.79% | 0 |

**同一条臂，瓶颈随 split 整体换位**：训练分布内四分之一的失败是计划太长，
组合泛化上超预算归零、失败全部变成目标未达成。这与 §4.4 的反转是同一个现象的两种测法。

### 4.10 目标解析的诊断

组合器路线的端到端分 ≈ 目标解析准确率。对零样本目标解析（94.70%）逐行诊断：

| | |
|---|---|
| 目标**召回** | 92.1% 的行预测谓词是真谓词的**超集** |
| 目标**精确** | 43.4% |

**瓶颈从来不是"看不懂任务"，是"多说了"和"顺序说错了"。** 这是把顺序交给记忆（§4.3）
而不是交给模型的直接依据。

### 4.11 Token 成本

`prompt_tokens` / `completion_tokens` 为服务端记录（Qwen2.5-VL-72B，含图像 token）；
`memory chars` 为**记忆注入 prompt 的字符数**，与图像和 tokenizer 无关，是各臂之间最干净的可比量。
本方法的 prompt 恰为 zero-shot 的 prompt 加上一段常量意图菜单，
故其 token 数按 1102 + 374 精确得出（374 由 Qwen2.5-VL tokenizer 实测；
Qwen2.5-VL 7B 与 72B 共用同一 tokenizer）。输出长度由归档响应实测。

| 方法 | 记忆注入 prompt 字符 | prompt tok | completion tok | 合计 tok | ID |
|---|---|---|---|---|---|
| zero-shot | 0 | 1102 | 411 | 1513 | 2.81% |
| skill memory v1（初版） | 839 | 1291 | 418 | 1709 | 7.58% |
| **skill memory v2（本方法）** | **1547（常数）** | **1476** | **71** | **1547** | **91.56%** |
| G-Memory | 2421 | 1680 | 473 | 2153 | 50.97% |
| skill memory v1（最好版本） | 3117 | 1988 | 481 | 2469 | 16.77% |
| trajectory RAG | 5100 | 2792 | 456 | 3248 | 6.71% |
| skill memory v1（grounded） | 7341 | 3349 | 484 | 3833 | 14.61% |

四点：

- **本方法比 G-Memory 少用 28% 的总 token，分数高 40.6 点**（1547 vs 2153 token，91.56% vs 50.97%）。
- **输出短 6 倍**（71 vs 473 token）。本方法让模型写一份简短的意图 JSON，而不是完整动作序列；
  这同时是它对上下文长度不敏感的原因。
- **记忆注入 prompt 的部分是常数 1547 字符**（意图菜单），**与行无关、与记忆规模无关**——
  19 个算子的算子库**从不进入 prompt**。其余每一个记忆方法注入的内容都随检索结果增长。
- **prompt 内容与分数无单调关系**：v1 的 grounded 版注入 7341 字符（是 G-Memory 的 3 倍）
  只得 14.61%。**"往 prompt 里塞更多记忆"这条轴在本 benchmark 上已经饱和**，
  这是把记忆改成可执行算子的直接动机（§4.1）。

补一条，已核实而非假定：**两条派工臂的 prompt 逐字节相同**——意图菜单是全脚本唯一的常量，
其中已包含 `robots` 字段，两条臂都拿到它，差别只在消费端是否采纳。输出长度分布一致
（均值 71、中位数 66），但**是两次独立生成**，不是同一批。

最强的证据是重打分自检：LLM 派工那批响应在记忆派工下重打分得 **846/924 = 91.56%**，
与记忆派工自己那批**完全一致**（两批 raw 有 908/924 逐字相同，其余 16 行不影响任何一分）。
**所以两条臂之间的差异不含任何 token 成本，也不含任何重采样方差。**

## 5. 基线的机制分析

两个最强基线**赢在哪里、输在哪里**都有对照实验，不是推测。这一节同时是对
"记忆方法在这个 benchmark 上到底在做什么"的度量。

### 5.1 G-Memory：检索贡献 11 点、格式范例贡献 6 点

把检索替换成均匀随机（`A9_GMEM_SHUFFLE=1`），其余完全不变：

| | 留出族 OOD |
|---|---|
| G-Memory（正常检索） | 20.78% |
| G-Memory（随机检索） | 9.52% |
| zero-shot | 3.46% |

配对 117/13，p=4.3e-22。**检索贡献约 11 点、格式范例贡献约 6 点**——
"它只是提供了输出格式范例"这个假说被否。

**但检索找到的是兄弟族。** 8 折中有 4 折，最近邻 90–100% 集中在单一近义族
（cut_fruit ↔ cut_two_fruits、toast_bread → set_plate），且**正是它拿 17.6–95.3% 的那四折**；
另四折检索散落，它拿 0–4.9%。在那 4 个"干净折"上，G-Memory 从 ID 的 29.8% 掉到 **0.9%**。

> family 划分比任务更细，所以按族留出挖掉的是**标签**而不是**分布**。
> 这一条同时说明：留出族 split 对轨迹检索类方法的真实难度，比折次平均分显示的更高。

### 5.2 MEMENTO-style：独立复现了其论文自己的信息过载结论

MEMENTO 的核心主张之一是分层类型分离可缓解信息过载。在本 benchmark 上按 top-k 扫描：

| 配置 | ID |
|---|---|
| 逐 episode，k=5，JSON | 6.7% |
| 按族聚合，k=3 | 8.3% |
| 逐 episode，k=2，JSON | 10.0% |
| 逐 episode，k=5，散文 | 11.7% |
| 按族聚合，k=5，散文 | 13.3% |
| **逐 episode，k=1，JSON** | **21.7%** |

（前六行为 60 行样本上的配置扫描，全量 924 行取最好配置得 19.91%。）

**k=5 → 6.7%、k=1 → 21.7%：信息过载在此独立复现。**
这是对其论文发现的一次独立验证,应当正面写。

**检索质量已自检**（`viki_diag_memento_retrieval.py`）：69.3% 的检索结果来自正确的族，
且检索到了逐字重复的指令。**所以其低分是真实结果，不是移植质量问题。**

**留出族逐折**：clear_table 0/220、set_plate 0/85、ensure_fruits 0/82、dog_push 0/46 全部为 0；
cut_two_fruits 2.78%、cut_fruit 4.23%、toast_bread 9.26%；只有 parallel_human 43.02%
（该族简单到通用知识即可）。**8 折里 5 折精确为 0。**

### 5.3 两个基线共享同一个上限

zero-shot 2.81% / trajectory RAG 6.71% / v1 16.77% / MEMENTO-style 19.91% / G-Memory 50.97%，
而 **top-5 逐字照抄天花板是 78.9%**。prompt 式方法的排序与其**检索召回率**排序一致：
在 92.5% 逐字泄漏的 ID split 上，"检索最近轨迹并照抄"接近最优，任何抽象都要先付出损失再挣回来。
这正是本方法把抽象放在**可执行算子**而不是**prompt 文本**上的动机（§4.1）。

## 8. 迁移到 PARTNR（第二个 benchmark）

框架是**"记忆买回特权"**：PARTNR 自带的 `heuristic_full_obs` 也从目标谓词符号组合，
但它**直接读 ground-truth 命题**（`scripted_centralized_planner.py:1178`）。本方法没有这个特权——
LLM 从指令产出命题，记忆补上特权原本提供的东西。上下界都由 PARTNR 自己给出。

### 8.1 评测格子的独立复原（方法学验证）

Memory-as-Skill 论文的任务类型划分由命题函数与约束独立重建，判据是
**只计 `TemporalConstraint` 的 `dag_edges`，不计 `evaluation_proposition_dependencies`**：

| 复原量 | 我们算出 | 论文报告 |
|---|---|---|
| val_mini 的 R_S episode 数 | **76** | "76 for R_S" |
| val 的 H_R_T episode 数 | **11** | "11–42" 的下界 |
| train_2k 的 H_R episode 数 | **197** | "up to 197" |

三个独立数字同时吻合。把 dependencies 也计为时序会让 R_S 从 76 塌到 14——
**判据被论文数字钉死，不是由我们选择的。** 这使后续所有 PARTNR 结果与论文可比。

### 8.2 消融 sweep（val = 1000 episode，零 token，指标 `task_percent_complete`）

ceiling = 中心化 + 全可观测 + 读 ground-truth 命题；v2 各臂 = 去中心化 + 部分可观测 + 算子归纳自 rollout。

| 任务类型 | n | ceiling | v2 R-only 记忆 | v2 全类型记忆 | −空间折叠 | −时序 DAG |
|---|---|---|---|---|---|---|
| R（重排） | 260 | 0.978 | 0.897 | 0.897 | 0.897 | 0.897 |
| R_S（+空间） | 261 | 0.939 | 0.841 | 0.864 | 0.859 | 0.828 |
| R_T（+时序） | 68 | 0.984 | 0.708 | 0.716 | 0.703 | 0.532 |
| R_S_T | 186 | 0.879 | 0.651 | 0.658 | 0.722 | 0.483 |
| H_R（+状态变更） | 207 | 0.918 | 0.325 | 0.592 | 0.325 | 0.325 |
| **全部** | **1000** | **0.9350** | **0.6919** | **0.7572** | **0.7093** | **0.6497** |

`task_state_success` 总表：0.8457 / 0.5472 / 0.6145 / 0.5257 / 0.4748。

三条结论：

1. **R 那一行五个臂逐位相同**（0.8973 / 0.8760）。所有开关都不影响它——
   rearrange-only 记忆的 6 条算子对纯重排充分且必要，同时这是全部消融开关的内部对照。
2. **时序 DAG 值 17–21 点，且精确落在有时序的任务上**（R_T 0.708→0.532、R_S_T 0.651→0.483，
   R 完全不变）。**与 VIKI-L2 上 Layer 2 的量级一致**（98.16% vs 77.38%，−20.8）。
3. **空间折叠是取舍**：R_S 折叠开 0.8414/0.7769、折叠关 0.8590/0.7259——
   用部分分换整题成功率，n=261 上划算（+5.1 / −1.8）。两个指标都需报告。

### 8.3 迁移边界

R-only 记忆在 207 个异质任务上 `task_state_success` 精确为 0.0000，
而 `task_percent_complete` 为 0.325：**一份只见过重排的记忆无法完成任何一个异质任务，
却仍能满足其中三分之一的单项要求。** 补上状态变更算子补回缺口的 45%（0.325 → 0.592）。
**迁移边界落在算子词表上**——与 VIKI-L2 上 `Push` 原语只存在于单一族的发现同构。
